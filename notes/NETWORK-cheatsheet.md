# Уорд, глава 9: сеть (разделы 9.1–9.12)

> В книге (2-е издание) часть команд старые: `ifconfig`, `route`, `netstat`. Сейчас их почти везде заменили на `ip` и `ss` — ниже везде даны современные варианты.

## Общая картина: слои

Данные по сети идут **пакетами**. Каждый слой добавляет к пакету свой «конверт» с адресом своего уровня.

| Слой | Что делает | Адрес / пример |
| --- | --- | --- |
| Прикладной | что передаём: веб-страницу, письмо | HTTP, SSH, DNS |
| Транспортный | какой программе на машине, надёжно или нет | порт: TCP, UDP |
| Сетевой (интернет) | до какого компьютера в любой сети | IP-адрес |
| Физический / канальный | до соседнего устройства в своей сети | MAC-адрес, Ethernet, Wi-Fi |

Аналогия: письмо (прикладной) кладут в конверт с именем получателя в доме (порт), потом в конверт с адресом дома (IP), а почтальон несёт его до ближайшего отделения (MAC). На каждом отделении меняется только внешний конверт.

## IP-адрес и подсеть

- IPv4-адрес — 4 числа от 0 до 255: `192.168.1.10`.
- Адрес делится на **сеть** и **хост**. Сколько бит отдано под сеть, задаёт маска.
- Запись `192.168.1.10/24` = первые 24 бита — сеть (`192.168.1`), последние 8 — номер компьютера в ней.

| CIDR | Маска | Адресов | Компьютеров |
| --- | --- | --- | --- |
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /16 | 255.255.0.0 | 65 536 | 65 534 |
| /32 | 255.255.255.255 | 1 | один конкретный адрес |

Два адреса в каждой подсети заняты: первый — **адрес сети** (`192.168.1.0`), последний — **широковещательный** (`192.168.1.255`). Отсюда 254, а не 256.

Как считать: адресов в подсети = 2^(32 − префикс). `/26` → 2^6 = 64.

Компьютеры **в одной подсети** общаются напрямую. Всё, что в другой подсети, — через **маршрутизатор** (шлюз).

## Маршруты

У ядра есть **таблица маршрутизации**: для каждого адреса назначения — куда отправить пакет.

```bash
ip route
```
```
default via 192.168.1.1 dev eth0         # всё остальное — на шлюз 192.168.1.1
192.168.1.0/24 dev eth0 proto kernel ... # своя сеть — напрямую, без шлюза
```

- **default** (шлюз по умолчанию) — куда отправлять всё, для чего нет более точного маршрута. Обычно это домашний роутер.
- Если подходят несколько маршрутов, выбирается **самый точный** — с самым длинным префиксом: `/24` важнее, чем `default` (это `/0`).
- Узнать, каким путём пойдёт пакет к адресу: `ip route get 8.8.8.8`.

## Инструменты диагностики

```bash
ping 8.8.8.8            # отвечает ли хост, сколько идёт ответ (Ctrl+C — стоп)
ping -c 4 ya.ru         # ровно 4 пакета
traceroute ya.ru        # через какие маршрутизаторы идёт путь (tracepath — если traceroute нет)
host ya.ru              # IP по имени (DNS)
dig ya.ru               # то же, но подробно; dig +short ya.ru — только адрес
```

- `ping` использует протокол **ICMP**. Его часто блокируют файрволы: «не пингуется» ≠ «не работает».
- `ping` по IP работает, а по имени нет → проблема в **DNS**, а не в сети.

## Интерфейсы

**Интерфейс** — то, через что ядро отправляет пакеты: сетевая карта, Wi-Fi, виртуальный интерфейс.

- `lo` — loopback, `127.0.0.1`: «сам себе», есть всегда.
- Проводные: `eth0` по-старому, сейчас чаще `enp3s0`, `ens33`. Wi-Fi: `wlan0`, `wlp2s0`.

```bash
ip a                    # все интерфейсы и их адреса (ip addr)
ip link                 # интерфейсы без адресов: состояние UP/DOWN, MAC
ip -br a                # то же коротко, по строке на интерфейс
```

В выводе ищи: `state UP` — интерфейс включён, `inet 192.168.1.10/24` — IPv4-адрес с маской, `link/ether` — MAC-адрес.

## Ручная настройка (до перезагрузки)

```bash
sudo ip link set eth0 up                          # включить интерфейс
sudo ip addr add 192.168.1.10/24 dev eth0         # назначить адрес
sudo ip route add default via 192.168.1.1         # шлюз по умолчанию
sudo ip route del default                         # удалить маршрут
sudo ip addr del 192.168.1.10/24 dev eth0         # убрать адрес
```

Всё это **пропадает после перезагрузки**. Поэтому вручную так делают только для проверки и при починке.

## Настройка при загрузке

- В книге — старые файлы вроде `/etc/network/interfaces`.
- В современной Ubuntu — **netplan**: YAML-файлы в `/etc/netplan/`, применить — `sudo netplan apply`.
- На серверах с другими дистрибутивами — NetworkManager или systemd-networkd.

## NetworkManager (9.11)

Служба, которая сама настраивает сеть: подключается к Wi-Fi, получает адрес по DHCP, переключается между сетями. Типично для ноутбуков и десктопов, бывает и на серверах.

```bash
nmcli device status          # интерфейсы и их состояние
nmcli connection show        # сохранённые подключения
nmcli device wifi list       # видимые Wi-Fi сети
```

## Как имя превращается в адрес (9.12)

Порядок, в котором система ищет IP по имени, задан в `/etc/nsswitch.conf` (строка `hosts:`). Обычно так:

1. **`/etc/hosts`** — локальная таблица «имя → адрес». Проверяется первой: так можно подменить любой адрес у себя.
2. **DNS** — сервер, указанный в `/etc/resolv.conf` (строка `nameserver`).

```bash
cat /etc/hosts
cat /etc/resolv.conf
getent hosts ya.ru           # ищет так же, как все программы: учитывает и /etc/hosts
```

`dig` и `host` спрашивают DNS напрямую и **не смотрят** в `/etc/hosts`. Если `dig` и браузер дают разные адреса — ищи запись в `/etc/hosts`.

## Что попробовать руками (в WSL безопасно, всё только чтение)

```bash
ip -br a
ip route
ip route get 8.8.8.8
ping -c 3 8.8.8.8 && ping -c 3 ya.ru
dig +short ya.ru
cat /etc/resolv.conf
getent hosts localhost
```

Менять адреса и маршруты в WSL не стоит: сеть там управляется Windows, и ты ничего полезного не увидишь, а связь можно сломать до перезапуска WSL. Ручную настройку оставь на будущую виртуалку.

## Карточки

Что видно на каждом слое: прикладном, транспортном, сетевом, канальном? :: Протокол (HTTP, SSH) / порт (TCP, UDP) / IP-адрес / MAC-адрес
Что значит `/24` в `192.168.1.10/24`? :: Первые 24 бита — сеть (`192.168.1`), последние 8 — номер компьютера
Сколько компьютеров поместится в `/24` и почему не 256? :: 254: адрес сети (`.0`) и широковещательный (`.255`) заняты
Сколько адресов в `/26`? :: 64 — это 2 в степени (32 − 26)
Маска для `/24` :: `255.255.255.0`
Могут ли `192.168.1.10/24` и `192.168.2.10/24` общаться без маршрутизатора? :: Нет: это разные подсети (`192.168.1` и `192.168.2`)
Что такое шлюз по умолчанию? :: Куда отправлять пакеты, для которых нет более точного маршрута. Обычно роутер
Посмотреть таблицу маршрутизации :: `ip route`
Каким путём пойдёт пакет к 8.8.8.8? :: `ip route get 8.8.8.8`
Подходят маршрут `192.168.1.0/24` и `default`. Какой выберет ядро? :: `/24`: побеждает самый длинный префикс, default — это `/0`
`ping 8.8.8.8` работает, `ping ya.ru` — нет. Где проблема? :: В DNS: сеть есть, не работает получение адреса по имени
Хост не отвечает на ping. Значит, он выключен? :: Не обязательно: ICMP часто блокируют файрволы
Через какие маршрутизаторы идёт путь до ya.ru? :: `traceroute ya.ru` (или `tracepath`)
Узнать IP по имени, только адрес :: `dig +short ya.ru`
Все интерфейсы и их адреса коротко :: `ip -br a`
Что такое `lo` и его адрес? :: Loopback, «сам себе», `127.0.0.1`
Назначить интерфейсу eth0 адрес 10.0.0.5/24 :: `sudo ip addr add 10.0.0.5/24 dev eth0`
Задать шлюз по умолчанию 10.0.0.1 :: `sudo ip route add default via 10.0.0.1`
Что будет с адресом, заданным через `ip addr add`, после перезагрузки? :: Пропадёт. Постоянная настройка — netplan, NetworkManager и т.п.
Где постоянная настройка сети в современной Ubuntu? :: netplan: `/etc/netplan/*.yaml`, применить `sudo netplan apply`
Посмотреть состояние сети в NetworkManager :: `nmcli device status`
В каком порядке ищется адрес по имени и где это задано? :: `/etc/nsswitch.conf`: обычно сначала `/etc/hosts`, потом DNS
Где указан DNS-сервер? :: `/etc/resolv.conf`, строка `nameserver`
`dig` и браузер дают разные адреса для одного имени. Почему? :: Скорее всего, запись в `/etc/hosts`: dig её не читает, а браузер и программы — да
Найти адрес так же, как его ищут программы, с учётом /etc/hosts :: `getent hosts имя`
Современные замены `ifconfig`, `route -n`, `netstat -tulpn` :: `ip a`, `ip route`, `ss -tulpn`
