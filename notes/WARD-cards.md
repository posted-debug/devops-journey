# Уорд, «Внутреннее устройство Linux» — карточки

Прочитано: главы 1–3, глава 4 до раздела «Типы файловых систем».

## Глава 1. Общая картина

Три основных уровня системы Linux :: Оборудование (память, процессор, устройства) → ядро → пользовательское пространство (процессы)
Чем режим ядра отличается от пользовательского режима? :: В режиме ядра код имеет неограниченный доступ к процессору и памяти; в пользовательском — только к своей части памяти и безопасным операциям процессора
Почему падение обычного процесса не роняет всю систему? :: Процесс ограничен своей памятью, последствия локальны, ядро их убирает
Что такое процесс? :: Запущенная программа, которой управляет ядро; по сути — состояние (образ) в памяти
Четыре главные задачи ядра :: Управление процессами, памятью, драйверами устройств; системные вызовы и поддержка
Что такое квант времени? :: Короткий отрезок, на который ядро отдаёт процессор процессу; кванты настолько малы, что кажется, будто процессы идут одновременно
Что такое переключение контекста? :: Ядро сохраняет состояние прерванного процесса, выбирает следующий готовый, готовит под него память и процессор и передаёт ему управление
Когда работает ядро, если процессор один? :: Между квантами процессов — во время переключения контекста
Что такое MMU и виртуальная память? :: Блок управления памятью в процессоре: процесс работает с виртуальными адресами, MMU переводит их в физические по картам ядра
Как называется таблица соответствия виртуальных и физических адресов? :: Таблица страниц
Почему с устройствами обычно работают только в режиме ядра? :: Неправильный доступ из процесса может обрушить систему, а драйверы ядра скрывают разные интерфейсы устройств за единым
Что такое системный вызов (syscall)? :: Просьба процесса к ядру сделать то, что процесс не может сам: открыть, прочитать, записать файл и т. п.
Что делает `fork()`? :: Ядро создаёт почти идентичную копию вызвавшего процесса
Что делает `exec(program)`? :: Ядро загружает программу и запускает её вместо текущего процесса
Как оболочка запускает `ls`? :: `fork()` создаёт копию оболочки, копия вызывает `exec(ls)` и превращается в ls
Какой процесс появляется не через `fork()`? :: `init` — первый процесс, его запускает ядро
Что такое псевдоустройство? :: Для процессов выглядит как устройство, но целиком программное, например `/dev/random`
Что такое пользовательское пространство (userland)? :: Память, которую ядро выделяет пользовательским процессам, и сами эти процессы
Как ядро различает пользователей? :: По числовому идентификатору (UID); имя — только для людей
Работает ли root в режиме ядра? :: Нет: суперпользователь может почти всё с чужими процессами и файлами, но всё равно работает в пользовательском режиме
Зачем нужны группы? :: Чтобы давать общие права на файлы сразу нескольким пользователям

## Глава 2. Основные команды и иерархия каталогов

Что такое `/bin/sh` и как он связан с bash? :: Bourne shell — стандартная оболочка Unix; bash — её расширенная версия, в Linux `/bin/sh` обычно ссылка на bash (в Debian/Ubuntu — на dash)
Как закончить ввод с клавиатуры в `cat` без аргументов? :: `Ctrl+D` — конец ввода (EOF)
Чем `Ctrl+D` отличается от `Ctrl+C`? :: `Ctrl+D` — конец ввода, программа завершается сама; `Ctrl+C` — сигнал INT, прерывание
Чем `locate` отличается от `find`? :: `locate` ищет по заранее построенному индексу (быстро, но может не знать о новых файлах); `find` обходит ФС прямо сейчас
Как следить за файлом, который дописывается (лог)? :: `tail -f file`
Отсортировать числа по убыванию :: `sort -nr` (`-n` — как числа, `-r` — в обратном порядке)
Что такое файлы с точкой (dot files)? :: Скрытые конфиги вроде `.bashrc`; `ls` и `*` их не показывают без `-a`
Чем переменная оболочки отличается от переменной окружения? :: Переменная оболочки видна только самой оболочке; `export` делает её переменной окружения, и её получают запущенные программы
Как оболочка находит команду? :: Идёт по каталогам из `PATH` слева направо и берёт первую найденную программу
Добавить каталог `dir` в начало PATH :: `PATH=dir:$PATH`
Чем опасна ошибка при присвоении PATH? :: Можно затереть PATH, и оболочка перестанет находить команды до конца сессии
Как подать файл на стандартный ввод команды? :: `<`, например `head < /proc/cpuinfo`
Из чего состоит сообщение об ошибке в Unix? :: Программа, объект (файл), ошибка: `ls: cannot access /x: No such file or directory`
Какую ошибку исправлять первой, если их много? :: Самую первую: остальные часто её следствие
`No such file or directory` — что за код ошибки системного вызова? :: `ENOENT`: файла или каталога нет
`touch a/b` → `Not a directory`. К какой части пути претензия? :: К `a`: это файл, а его используют как каталог
`Permission denied` vs `Operation not permitted` :: Первое — нет прав на файл/каталог; второе — например, попытка убить чужой процесс
Что значит `Segmentation fault`? :: Программа полезла в память, к которой нет доступа, и ядро её завершило; обычно баг в программе
Опции `ps` в стиле BSD: `x`, `ax`, `u`, `w` :: `x` — все свои процессы; `ax` — все процессы системы; `u` — подробно; `w` — полные команды
Посмотреть процесс текущей оболочки :: `ps u $$`
Какой сигнал шлёт `kill PID` по умолчанию? :: TERM
Какой сигнал шлёт `Ctrl+C`? :: INT
Что делают `kill -STOP` и `kill -CONT`? :: Останавливают процесс (он остаётся в памяти) и продолжают его с того же места
Список сигналов с номерами :: `kill -l`
Что делает `Ctrl+Z` и как вернуть процесс? :: Шлёт TSTP и приостанавливает; `fg` — вернуть на передний план, `bg` — продолжить в фоне, `jobs` — список заданий
Запустить команду в фоне, чтобы она пережила выход из ssh :: `nohup cmd &`
Из чего состоит строка прав `-rw-r--r--`? :: Тип файла (`-` файл, `d` каталог, `l` ссылка), потом rwx владельца, группы и остальных
Дать группе и остальным право чтения символьно :: `chmod go+r file` (убрать — `go-r`)
Что такое setuid (`s` вместо `x` у владельца)? :: Программа запускается с правами владельца файла, а не того, кто её запустил; так `passwd` получает права root
Порядок аргументов в `ln -s` :: `ln -s цель имя_ссылки` — сначала на что ссылаемся, потом имя ссылки
Чем неудобны символьные ссылки? :: Могут указывать в никуда (битая ссылка), а длинные цепочки ссылок путают
Что делает `gzip file`? :: Сжимает в `file.gz` и удаляет оригинал; `gunzip file.gz` — обратно
`tar`: `cvf`, `xvf`, `tvf` :: Создать архив, распаковать, показать содержимое (`v` — подробно, `f` — файл архива)
Распаковать `.tar.gz` одной командой :: `tar zxvf file.tar.gz`
Что делает `zcat`? :: То же, что `gunzip -c`: выводит распакованное содержимое в stdout, не трогая файл
`/proc` :: Интерфейс к ядру и процессам, не на диске: `/proc/cpuinfo`, `/proc/<PID>/`
`/sys` :: Интерфейс к устройствам и системе (sysfs)
`/sbin` :: Системные программы, обычно для администрирования
`/lib` :: Разделяемые библиотеки (и модули ядра в `/lib/modules`)
`/var` :: Изменяемые данные программ: логи (`/var/log`), кэши, `/var/tmp` переживает перезагрузку
`/tmp` :: Временные файлы, может очищаться при загрузке
`/usr` :: Основная часть программ и данных (`/usr/bin`, `/usr/lib`, `/usr/share`); `/usr/local` — то, что ставишь сам
`/boot`, `/opt`, `/run` :: Ядро и загрузчик; сторонний софт; данные времени выполнения (PID-файлы, сокеты), чистится при перезагрузке
Где лежит ядро Linux? :: `/vmlinuz` или `/boot/vmlinuz`
Почему `sudo` лучше постоянной работы под root? :: Права root только на нужную команду, всё логируется, пароль root не нужен
Где настраивается sudo и как его править? :: `/etc/sudoers`, только через `visudo` — он проверяет синтаксис
Где посмотреть, что запускали через sudo? :: `journalctl SYSLOG_IDENTIFIER=sudo`

## Глава 3. Устройства

Где лежат файлы устройств? :: В `/dev`
Что значат `b`, `c`, `p`, `s` первым символом в `ls -l`? :: Блочное устройство, символьное, именованный канал, сокет
Блочное устройство :: Данные читаются блоками фиксированного размера, есть произвольный доступ и известный размер — диски (`sda`)
Символьное устройство :: Поток байтов без размера и произвольного доступа — терминалы, `/dev/null`, принтеры
Именованный канал (pipe) :: Устроен как символьное устройство, но на другом конце другой процесс, а не драйвер ядра
Сокет :: Интерфейс для связи между процессами, часто лежит вне `/dev`
Что за числа `8, 1` в `ls -l /dev/sda1`? :: Старший (major) и младший (minor) номера: по ним ядро находит драйвер и конкретное устройство
Почему у сетевой карты нет файла в `/dev`? :: Не всё укладывается в блочный или символьный интерфейс; сетевые интерфейсы ядро даёт по-другому
Что такое sysfs и где базовый путь? :: Интерфейс ядра с реальной иерархией устройств по железу; `/sys/devices`
Что лежит в `/sys/block`? :: Ссылки на все блочные устройства системы
Путь в sysfs и все атрибуты устройства `/dev/sda` :: `udevadm info --query=all --name=/dev/sda`
`dd`: что значат `if`, `of`, `bs`, `count`, `skip` :: Входной файл, выходной файл, размер блока, сколько блоков скопировать, сколько блоков пропустить на входе
Почему `dd` опасна? :: Перепутал `if` и `of` — затёр диск, и никто не переспросит
`/dev/sd*` :: Диски через подсистему SCSI (SATA, USB): `sda`, `sdb`, разделы `sda1`
`/dev/vd*`, `/dev/xvd*` :: Виртуальные диски в виртуальных машинах (virtio, Xen) — их увидишь на VPS
`/dev/nvme*` :: NVMe SSD: диск `nvme0n1`, разделы `nvme0n1p1`
`/dev/dm-*` и `/dev/mapper/*` :: Блочные устройства device mapper, например тома LVM
`/dev/sr*` :: CD/DVD-приводы
`/dev/tty*`, `/dev/pts/*`, `/dev/tty` :: Виртуальные консоли и терминалы; псевдотерминалы (окна терминала, ssh-сессии); управляющий терминал текущего процесса
Как узнать, в каком терминале ты сидишь? :: `tty`
`/dev/ttyS*`, `/dev/ttyUSB*`, `/dev/ttyACM*` :: Последовательные порты: встроенные COM, USB-переходники, USB-устройства класса ACM
Чем создать файл устройства вручную? :: `mknod`, но сейчас этим занимаются devtmpfs и udev
Что такое devtmpfs? :: Файловая система, в которой ядро само создаёт файлы устройств, как только их находит
Что делает udev (демон `udevd`)? :: Получает события ядра (uevent) и по правилам донастраивает устройства: права, ссылки, понятные имена
Где лежат правила udev? :: `/lib/udev/rules.d` (системные) и `/etc/udev/rules.d` (свои)
Зачем `/dev/disk/by-id` и `/dev/disk/by-uuid`? :: Постоянные имена дисков от udev: не меняются, в отличие от `sda`/`sdb`, которые могут поменяться местами
Смотреть события устройств в реальном времени :: `udevadm monitor` (`--kernel` — только события ядра)
Почему и SATA-диск, и флешка называются `sd*`? :: Ядро работает с обоими через подсистему SCSI: USB-накопители говорят на SCSI, для SATA есть слой трансляции
Список SCSI-устройств :: `lsscsi`
Что такое `/dev/sg*`? :: Обобщённые SCSI-устройства: прямой доступ к SCSI-командам для специальных программ

## Глава 4. Диски и файловые системы (до типов ФС)

Как называются разделы в Linux? :: Имя диска + номер: `sda1`, `sdb3`; у NVMe — `nvme0n1p1`
Что такое таблица разделов? :: Данные о том, как блоки диска поделены на разделы
MBR и GPT — в чём разница? :: MBR — старая схема с ограничениями (4 основных раздела, диски до ~2 ТБ); GPT — новая, без этих ограничений
Основной, расширенный и логический раздел в MBR :: Основных максимум 4; чтобы сделать больше, один делают расширенным, внутри него логические (номера с 5)
Чем посмотреть таблицу разделов? :: `parted -l` (приблизительные размеры) или `fdisk -l` (точно, в секторах)
Коды типов разделов MBR `83`, `82`, `8e` :: Linux, swap, LVM
Как ядро пишет в лог расширенный раздел? :: `sda: sda1 sda2 < sda5 >` — `sda5` логический внутри расширенного `sda2`; смотреть через `journalctl -k`
Признаки того, что в системе LVM :: Разделы с типом lvm (`8e`), устройства `/dev/dm-*`, `/dev/mapper/...`
Главное отличие `fdisk` и `parted` при изменениях :: `fdisk` копит изменения и пишет всё только по `w`; `parted` применяет каждую команду сразу
Команды `fdisk`: `p`, `d`, `n`, `w`, `q` :: Показать таблицу, удалить раздел, создать раздел, записать и выйти, выйти без сохранения
Что сделать перед изменением таблицы разделов? :: Бэкап данных и убедиться, что разделы этого диска не смонтированы
Создать раздел на 200 МБ в `fdisk` :: `n`, тип `p`, номер, первый сектор по умолчанию, последний `+200M`
Заставить ядро перечитать таблицу разделов :: `blockdev --rereadpt /dev/sdX`
Где увидеть изменения разделов? :: `/proc/partitions`, `/sys/block/<диск>/`, `udevadm monitor --kernel`
Почему геометрии CHS (цилиндры, головки) у современных дисков нельзя верить? :: Диск сам транслирует адреса (LBA) и скрывает реальное устройство; на границы цилиндров можно не смотреть
Зачем выравнивать разделы на SSD? :: SSD читает страницами (4096, 8192 байт); раздел не на границе страницы — лишние чтения и медленнее
По какой границе утилиты выравнивают разделы сейчас? :: 1 МБ = 2048 секторов по 512 байт
Как проверить выравнивание раздела `sdf2`? :: `cat /sys/block/sdf/sdf2/start` — смещение в 512-байтовых секторах; для страниц 4096 байт должно делиться на 8
Что такое файловая система? :: База данных, которая превращает блочное устройство в иерархию файлов и каталогов
Что такое VFS? :: Виртуальная файловая система: слой ядра с единым интерфейсом, чтобы программы одинаково работали с любой ФС
Почему `/proc` и `/sys` — тоже файловые системы, хотя их нет на диске? :: Интерфейс файлов и каталогов универсален, через него удобно показывать системную информацию
